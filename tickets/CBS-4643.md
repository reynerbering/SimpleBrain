**Decisions**

- Decisions live in the design doc, not here. Link, do not duplicate. **There is no design doc for this ticket** — the two decisions below were made in-session and have nowhere else to live yet, so they are recorded here until one exists.
- **Assert the emitted predicate, not the generated parameter name.** EF9's `__jobId_Value` became EF10's `@jobId_Value`. Matching `[j].[job_id] =` tests what the CBS-4654 regression guard is actually for and does not move when the translator renames a parameter. Rejected: pinning the new spelling — same brittleness, one upgrade later.
- **Record container schema drift in the repo and apply it before the suite, rather than fixing the container by hand.** A hand-run `ALTER` is invisible to the next person and to a fresh container. Rejected: failing loudly with a clear message instead of self-healing — it diagnoses but still leaves the suite red for the same amount of work.
- **An unreachable database is not a failure in the new hook.** The fixtures' own `InitializeDatabaseConnectionsAsync` reports a missing container far more clearly, and the DB-free `Service_Tests` must keep running without Docker.

**Coverage gaps found — behaviour is correct, the suite just does not pin it.** Verified with throwaway probe tests, run and then deleted; nothing was committed.

- **`sortMode`'s default cannot be verified against the current fixture.** `added` and `position` both return `[1,2,3]` on the seed data, so if the default flipped to `position` no test would fail. AC1's "defaults to `added`" is the one AC clause with no real assertion behind it. Fixing it needs a seed job whose position ordering differs from its created-date ordering.
- **4 of the 7 allowed values are never sent on a success path** — `position`, `asc`, `active`, `expired` appear only inside the 400-message assertions. Probed: `active` → `[1,2]`, `expired` → `[3]`, `asc` → `[3,2,1]`, `position` accepted. All correct, none pinned.
- **Unparseable non-blank dates return 400, untested.** Beyond AC3, which only covers blank. Probed: `startDate=not-a-date` → `400 Invalid value 'not-a-date' for parameter 'startDate'. Expected a date.`
- **`sortDirection`'s desc default is real** — probed blank and omitted both `[1,2,3]` against `desc` `[1,2,3]` / `asc` `[3,2,1]`. The six "DefaultsTo..." tests assert only the record count, so their names claim more than they check.
- `TryReadProcedureError`'s empty-message fallback string is unreachable by any test. Minor.
